# Review: U04 / `91633c5` — MikaOperationFacade pin to registry

**Commit:** `91633c587de4ebdcf946008ffb10ba1d01edbe93`

**Scope:** `src/api/operation-facade.ts` (+32 lines)

## Summary

Adds a compile-time set-equality pin between the hand-written full facade surface (`MikaServerOperationFacade` = storefront + webhook + admin) and registry-derived `MikaOperationFacadeSpec` (ops with `apiMethod !== false`, same filter already used by `collectMikaOperationFacadeSpec` / `MikaFacadeOperationDefinitionKey`).

The pin is three-way and genuinely bidirectional:

1. **`MikaFacadeSpecMethodDrift`** — methods on the registry/spec missing from the hand facade  
2. **`MikaFacadeInterfaceMethodDrift`** — methods on the hand facade missing from the registry/spec  
3. **`MikaFacadeNamespaceDrift`** — namespace key-set mismatch either direction  

`MikaFacadeRegistryDrift` unions those; `_AssertMikaFacadePinnedToRegistry` resolves to `true` when locked, otherwise to the drift union (so a failure surfaces the offending keys instead of only `never`). The `const … = true` + `void` pattern matches U03/U05 and stays erasable / non-exported.

Choosing **`MikaServerOperationFacade`** (not bare `MikaOperationFacade`) is correct: admin and webhook are part of the registry facade surface and would otherwise remain unpinned. Scope is method/namespace **presence**, same practical bar as U03’s `MikaApi` name-map pin — not call signatures or input dual-truth (later P1).

No public export surface change; runtime `createMikaOperationFacade` is unchanged. Interface assignability on the builder still requires hand method bodies for every interface method; the new pin closes the registry ↔ hand-interface gap that assignability alone does not.

**Verdict:** Accept. Closes P0.2 / U04 as specified. No blocking defects.
