## 2. Circular imports

### 2.1 ACP (`src/acp/*`)

```text
constants, types          (leaves)
crypto          → constants
mappers         → types
feed            → types
session-store   → types, constants, mappers
handlers        → types, constants, crypto, mappers, session-store
acp.ts barrel   → types, constants, feed, session-store, mappers, handlers
```

**Acyclic.** No module imports the package barrel (`../acp` / `../../acp`).

### 2.2 Stripe (`src/stripe/*`)

```text
types, helpers → types
checkout | actions | webhooks → types, helpers
provider → types, checkout, actions, webhooks, helpers
stripe.ts barrel → types, provider
```

**Acyclic.**

### 2.3 Checkout (`src/api/backend/checkout/*`)

```text
helpers (leaf among checkout modules)
preview | status | cancel → helpers
start → helpers, status, preview
checkout.ts barrel → start, status, cancel, preview, helpers
```

**Acyclic** within checkout. Siblings correctly use `./helpers` / `./status` / `./preview`, not the barrel.

### 2.4 Payment (`webhooks/payment/*`)

```text
shared → ../../checkout (barrel)
subscription → (shared deps as needed)
payment-event → shared, ../../checkout (barrel)
process → shared, payment-event, subscription
payment.ts barrel → process, shared
```

**No cycle today** (checkout does not import payment).  

**Soft risk (P2):** `payment/shared.ts` and `payment/payment-event.ts` import from the **checkout barrel** (`../../checkout`) rather than `../../checkout/helpers` and `../../checkout/status`. That:

1. Forces evaluation of the full checkout graph (including heavy `start.ts`) when loading payment.
2. Creates a future cycle hazard if any checkout module ever imports a payment helper via the payment barrel.

Prefer direct sibling paths on the next touch of those files.

## 3. Behavior preservation risks

Roadmap/execution rule: *do not combine megafile splits with behavior changes.*

### 3.1 Money-path runtime (checkout / payment / stripe / ACP handlers)

- Public and internal **export sets match parent** (§1) — no intentional API reshape.
- Payment `processStoredWebhook` switch structure (paid / refund / expired / subscription / unknown) is preserved in `payment/process.ts`.
- Stripe factory still composes the same adapter methods via `defineMikaProvider` in `provider.ts`.
- Checkout factory wiring unchanged (`factory.ts` still binds the same four operations from the checkout barrel).

**Residual risk:** this is a ~7k-line mechanical move; line-level equivalence was not proven with a formal old/new AST or golden diff of function bodies. Confidence is **high but not mechanical-proof**. Recommend relying on existing `test/backend.test.ts` / ACP / Stripe suites rather than assuming the split is bug-free without CI green.

### 3.2 Duplicated `parseAcpItemId` (ACP)

| Location | Status |
| -------- | ------ |
| Parent megafile | single private `function parseAcpItemId` |
| `handlers.ts` | `export function` — used by `reconcileAcpCart` |
| `mappers.ts` | `export function` — **unused** |

Today bodies match. If they diverge, cart reconcile vs any future mapper consumer could disagree on sellable/price parsing. **Nit / maintainability** — not a current behavioral break.

### 3.3 Type-guard weakenings (not a pure split)

#### `MikaFacadeRegistryDrift` (`src/api/operation-facade.ts`)

**Before:** bidirectional union —

1. registry methods missing on hand facade  
2. hand methods missing from registry  
3. namespace set mismatches both ways  

**After:** only (1) — registry method keys ⊆ hand facade method keys (with missing-namespace still surfacing via `Exclude<…, never>`).

Comment still says **“Bidirectional pin”** but the type is **unidirectional**. Extra hand methods/namespaces no longer fail `_AssertMikaFacadePinnedToRegistry`.

#### `MikaActionsRegistryDrift` (`src/astro-actions.ts`)

Symmetric simplification. Partial coverage remains via `MikaActionsTreeCoversInterface` (tree must cover hand method positions), but **extra tree methods** / some namespace-only mismatches are easier to miss at compile time. Runtime `validateMikaActionTreeSpec` still helps for action defs.

**Severity:** Medium (compile-time drift armor regression; no direct runtime change). **Should not have ridden with U17–U20** under the “no behavior changes with megafile splits” rule unless required to unblock typecheck — and if so, that should be called out in the commit body.

### 3.4 U21 dispatch cast note (`operation-define.ts`)

- Comment documents that `as unknown as Record` is intentional and localized; prefers explicit `call` on money-moving ops; warns against new `as unknown as MikaApi` casts.
- Cast implementation itself is unchanged.
- Roadmap also mentioned “lint against new ad-hoc casts” — **not implemented** (acceptable as “if cheap”; mark U21 as comment-only containment).

Repo scan of `as unknown as` under `src/api`: still only `operation-define.ts` (dispatch), plus unrelated `admin-audit` / `validation` casts. No new ad-hoc `MikaApi` casts introduced here.

### 3.5 Previously private constants now module-exported

`MIKA_ACP_DEFAULT_SESSION_TTL_MS`, claim TTLs, signature tolerance, etc. were file-private `const`s; they are now `export const` in `acp/constants.ts` but **not** on the package barrel. No published API change; source-tree importers could reach them if they deep-import package sources (not supported).
