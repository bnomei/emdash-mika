## Summary

Additive package subpath `@bnomei/emdash-mika/types/primitives` for branded primitives, constructors, type guards, and domain enums — without the full wire DTO barrel on `@bnomei/emdash-mika/types`. That is exactly what ROADMAP P3 / external-api-surface recommendation #12 asked for: optional discoverability, non-breaking.

Wiring is complete for a publishable entry:

| Layer | Change |
| ----- | ------ |
| `package.json` `exports` | `./types/primitives` → `dist/types/primitives-entry.{d.mts,mjs}` (`types` + `import` only) |
| `build:pack` | Adds `src/types/primitives-entry.ts` next to other type entries |
| `tsconfig` paths | Maps package subpath → `primitives-entry.ts` for workspace/source resolution |
| Export-map pin | `test/index.test.ts` “public types” expected keys include `./types/primitives` |

The new entry is an **explicit allowlist** re-export of `./primitives`, not `export *` and not packing `primitives.ts` as the public root. That matches how `/types` already surfaces primitives (value + type lists in `src/types/index.ts`) and deliberately keeps the public set stable if `primitives.ts` later grows internal-only exports.

Compared symbol-for-symbol to the primitive block on `/types` (`src/types/index.ts` L94–145):

- **Value exports:** identical (`create*` / `is*` set).
- **Type exports:** identical set (order differs slightly; no functional impact).
- **Not re-exported (parity with `/types`):** `CheckoutProviderStatus` remains source-only on `primitives.ts` (used by documents / API helpers; not on either public barrel today). Pre-existing; this commit does not widen or shrink that surface.

**Verdict:** Accept. Closes P3 optional `./types/primitives` / U28 as specified. Discoverability and contract tests are slightly incomplete relative to sibling type subpaths (README + `package-exports`); no functional defect in the export itself.

## Issues

### Issue 1 -- Severity: suggestion
- File: `README.md` (~L367–371); `test/index.test.ts` (~L4419–4429)
- Description: Root README documents the public type barrels as `/types` plus aggregates / documents / operational only. The new primitives subpath is the whole point of “discoverability,” but hosts reading the package surface list will not see it. The README alignment test already pins the three storage barrels and would be the natural place to require `@bnomei/emdash-mika/types/primitives` once README is updated.
- Suggestion: Extend the bullet to four barrels, e.g. branded primitives on `/types/primitives` and storage model on aggregates/documents/operational; add the package path to the README pin test (same pattern as the three existing pins). Optionally mention `/types/primitives` in the `src/types/index.ts` file header sibling list for in-source discoverability.
- Status: open

### Issue 2 -- Severity: suggestion
- File: `test/package-exports.ts`; (related) `src/types/primitives-entry.ts`
- Description: Compile-time package contract (`test/package-exports.ts`) imports sample symbols from `@bnomei/emdash-mika/types/aggregates`, `/types/documents`, `/types/operational`, and `/types`, but not from `/types/primitives`. The runtime export-map key pin in `index.test.ts` would catch a missing `exports` key; it would **not** catch a broken path mapping, empty barrel, or DTS emit that fails to re-export e.g. `createMikaId` / `MikaId` under the package subpath. Sibling type entries already use this import-as-contract pattern.
- Suggestion: Add a small type import block, e.g. `createMikaId`, `MikaId`, `CurrencyCode`, `Money` from `@bnomei/emdash-mika/types/primitives`, and (optional) pin them into `PackageEntryContract` the same way other subpaths are sampled. Stronger follow-up (not required for U28): assert export-name parity between `/types` primitive symbols and `/types/primitives` so the duplicated allowlists cannot drift.
- Status: open

### Issue 3 -- Severity: nit
- File: `src/types/primitives-entry.ts` vs `src/types/index.ts` L94–145
- Description: The value and type allowlists are copy-pasted. Correct today; any new public primitive (constructor, guard, brand, or enum) requires two edits or `/types/primitives` silently lags `/types`.
- Suggestion: Acceptable for an optional P3 entry. Prefer either (a) a shared re-export module both barrels import, or (b) a lightweight test that the primitive symbol set on `/types` equals the set on `/types/primitives`. Do not switch to bare `export * from "./primitives"` without an explicit product decision to publish `CheckoutProviderStatus` (and any future internal exports).
- Status: open

### Issue 4 -- Severity: nit
- File: `src/types/primitives-entry.ts`; `package.json` exports
- Description: Dist artifacts are named `primitives-entry.{mjs,d.mts}` while the public subpath is `./types/primitives`. Sibling type subpaths map 1:1 (`aggregates.ts` → `aggregates.mjs`). The entry-file pattern is sound (explicit public surface ≠ internal module), and consumers only use the package path, but the naming is a small inconsistency for maintainers reading `dist/`.
- Suggestion: No change required. If renaming ever comes up, either pack `primitives.ts` under an allowlist wrapper with a dist basename of `primitives`, or document why `*-entry` exists in a one-line comment on the exports map / entry file (the existing file comment already explains role).
- Status: open

## Non-issues / confirmed correct

- **Allowlist vs packing `primitives.ts` directly:** Correct. Prevents accidental publication of every export from the internal module; mirrors `/types`’s curated primitive surface.
- **Export conditions:** Only `types` + `import`, same as other package entries; covered by the existing loop in `public types` tests.
- **No `./api` / deep `src` leakage:** Unchanged negative tests still apply.
- **Order in `build:pack` / `exports`:** Placed with other type entries; tsconfig path and exports target the same source file.
- **Runtime duplication:** Separate pack entries may embed the same constructors/guards as `/types`. Same class of tradeoff as multi-entry packages generally; acceptable for an optional narrow import path.
- **Roadmap / commit message:** Matches P3 optional subpath; verify list (test, pack:check, types:check, templates:check) is appropriate for an export-map unit (templates:check is unrelated but harmless if run as full gate).
- **`CheckoutProviderStatus` omission:** Pre-existing on `/types`; not a regression of this unit. If product wants it public, that is a separate barrel-completeness change on both `/types` and `/types/primitives`.
