## Summary

The **operations split (U16)** is a clean mechanical extraction along the seams already recommended in `typescript-internals-improvements.md`: helpers/overloads → catalog → derived registries, with `operations.ts` re-exporting the prior public surface. Call sites that import from `./operations` need not change; structural tests were retargeted at the new files. No behavioral risk found in the move itself.

**Entity brands (U23)** land as optional soft brands + constructors on `/types`. That matches the unit’s “types only first” intent and keeps `MikaId` as the escape hatch. Cross-entity assignability is only partially closed (see Issue 3). Zod mint helpers and money-path migration correctly remain follow-ups (U24 / roadmap open items).

**declarationMap (U26)** flips the root flag and disables it in test tsconfigs — correct for package vs test emit. Maps do appear under `dist/`, but jump-to-source for npm consumers is incomplete without published sources or a remapped `sourceRoot` (Issue 4).

**Error taxonomy + ACP allowlist (U22)** is the risk center. Adding `IDEMPOTENCY_MISMATCH`, `WEBHOOK_DEFERRED`, and `STOCK_CONFLICT` is additive and welcome. Switching ACP from `error.code.toLowerCase()` to an exhaustive `satisfies Record<MikaErrorCode, …>` map is the right control. However, the map **renames several existing wire codes**, and in particular maps **every** `CONFLICT` to `request_not_idempotent` while emission sites still over-use `CONFLICT` for cart CAS, stock undercut, webhook deferred, and other non-idempotency 409s. Until those call sites emit the new codes (or the map is narrowed), ACP clients can misclassify failures. That is a correctness/compatibility regression relative to the prior lowercase projection, not merely incomplete polish.

**Verdict:** **Accept with required follow-up before treating U22 as done for ACP wire safety.** U16 and U26 are fine as scoped; U23 is an acceptable first slice; U22’s enum addition is good, but the allowlist’s `CONFLICT` (and auth) remaps need a deliberate emission-site migration or a safer default mapping.

## Issues

### Issue 1 — Severity: **high** (correctness / ACP wire)

- **Area:** U22 ACP allowlist · `MIKA_TO_ACP_ERROR_CODES.CONFLICT`
- **File (commit):** `src/acp.ts` (current tree: `src/acp/mappers.ts`)
- **Description:**  
  Previously ACP wire codes were `error.code.toLowerCase()`, so Mika `CONFLICT` became ACP `"conflict"`. The new map forces:

  ```ts
  CONFLICT: "request_not_idempotent",
  IDEMPOTENCY_MISMATCH: "request_not_idempotent",
  ```

  Backend still emits **`CONFLICT` for many non-idempotency failures**, including (non-exhaustive):

  | Helper / site | Meaning |
  | ------------- | ------- |
  | `checkoutIdempotencyInputMismatch` | true idempotency mismatch — still `CONFLICT`, not `IDEMPOTENCY_MISMATCH` |
  | `webhookProcessingDeferred` | deferred webhook — still `CONFLICT`, not `WEBHOOK_DEFERRED` |
  | `factory` stock `would_undercut_reserved` / `would_go_negative` | stock CAS — still `CONFLICT`, not `STOCK_CONFLICT` |
  | `cart.ts` locked / version / create races | concurrency — not idempotency-key reuse |
  | `checkoutPersistenceFailed`, `checkoutFailedReplay`, subscriptions, admin-audit | various 409s |

  Effect: ACP clients that treat `request_not_idempotent` as “retry with a new Idempotency-Key” will mis-handle cart locks, stock undercut, and deferred webhooks. The new Mika codes do not help until emission sites migrate; the map change already changes the wire for all remaining `CONFLICT`s.

- **Suggestion:**  
  1. **Default `CONFLICT` to a neutral ACP code** (e.g. keep `"conflict"` via the `Lowercase<MikaErrorCode>` arm, or `"invalid_request"`) **unless** the Mika code is specifically idempotency-related.  
  2. Migrate emitters in the same or immediate follow-up unit:
     - `checkoutIdempotencyInputMismatch` / admin idempotency mismatch → `IDEMPOTENCY_MISMATCH`
     - `webhookProcessingDeferred` → `WEBHOOK_DEFERRED`
     - stock undercut / analogous CAS → `STOCK_CONFLICT`
  3. Only map `IDEMPOTENCY_MISMATCH` (and true key-reuse paths) to `request_not_idempotent`.  
  4. Add ACP tests that assert wire codes for non-idempotency `CONFLICT` fixtures (e.g. cancel locked checkout currently uses `code: "CONFLICT"` without asserting the ACP code).

- **Status:** open — **blocks calling U22 “done” for ACP safety**

### Issue 2 — Severity: **medium** (ACP wire compatibility)

- **Area:** U22 auth / CSRF remaps
- **Description:** Allowlist also changes existing projections:

  | Mika | Before (toLowerCase) | After |
  | ---- | -------------------- | ----- |
  | `AUTH_REQUIRED` | `auth_required` | `unauthorized` |
  | `FORBIDDEN` | `forbidden` | `unauthorized` |
  | `CSRF_INVALID` | `csrf_invalid` | `unauthorized` |

  Collapsing to `unauthorized` may match ACP product vocabulary, but it is a **breaking wire change** for any ACP client branching on the old lowercase Mika codes. Unlike Issue 1, this may be intentional protocol normalization — it still needs an explicit changelog / ACP doc note and preferably tests.

- **Suggestion:** Document as intentional ACP normalization in agentic/ACP docs; add a small table test over `MIKA_TO_ACP_ERROR_CODES` for stable expected wires; if external agents already shipped, consider a dual-publish window or keep distinct codes where the protocol allows.

- **Status:** open

### Issue 3 — Severity: **medium** (type safety completeness — U23)

- **Area:** Entity brands · `src/types/primitives.ts`
- **Description:** Brands are implemented as:

  ```ts
  export type SellableId = MikaId & { readonly __mikaEntity?: "SellableId" };
  export function createSellableId(value: string): SellableId {
    return createMikaId(value) as SellableId;
  }
  ```

  Consequences:

  1. **`MikaId` remains assignable to every entity brand** (optional phantom may be absent), so wrong-entity bugs still typecheck when values are typed as `MikaId` (the common DTO shape today).
  2. Phantom uses a string key `__mikaEntity` rather than a `unique symbol` brand (memo’s preferred shape); weaker nominality and a slightly leaky public property name if ever set.
  3. Constructors do not set `__mikaEntity` at runtime (type-only), which is fine for brands but means no runtime discrimination.
  4. Roadmap bullet “constructors + **Zod mint helpers**” is only half-landed (explicitly noted as follow-up).

  Acceptable for U23 “introduce types,” but **does not yet deliver** the monotype-`MikaId` fix until U24 migrates money boundaries and Zod mints brands at parse edges.

- **Suggestion:** Keep as soft brands for the transition; document assignability policy next to the types; in U24 prefer `unique symbol` (or distinct brand fields) if hosts start relying on cross-entity rejection; add Zod `createSellableId` mints on cart/checkout inputs.

- **Status:** open (expected residual for U23 slice)

### Issue 4 — Severity: **medium** (consumer DX — U26 incomplete)

- **Area:** `declarationMap` + package contents
- **Evidence:** `dist/*.d.mts.map` sources point at paths like `"../src/types/primitives.ts"`, while `package.json` `"files"` is only `["dist", "src/templates"]`. Published npm installs therefore ship maps that resolve to **missing** sources for most modules.
- **Description:** Enabling `declarationMap` satisfies the tsconfig checklist item and grows `dist` with `.d.mts.map` files, but **jump-to-definition to implementation source will not work for typical consumers** without either:
  - publishing relevant `src/**` (or a `src` subset), or
  - rewriting map `sourceRoot` / sources to a stable GitHub URL (or bundling sources into dist).
- **Suggestion:** Either (a) document that declaration maps currently help monorepo / linked dev only, or (b) follow up with `files` / `sourceRoot` so published packages fulfill the polish goal. Confirm `vp pack` + publint still happy with map volume (already in dist locally).

- **Status:** open

### Issue 7 — Severity: **low** (ACP type surface)

- **Area:** `MikaAcpError["code"]` still includes `Lowercase<MikaErrorCode>`
- **Description:** Runtime no longer auto-lowercases, but the **type** still allows any lowercased Mika code. Combined with remaps to `unauthorized` / `request_not_idempotent`, the declared union is wider than the allowlist’s actual range.
