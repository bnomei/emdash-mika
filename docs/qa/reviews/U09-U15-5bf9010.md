## Verdict

**Approve with follow-ups (non-blocking for additive surface; blocking for peer-honesty residual).**

The commit does the right product work for U09 + U15 and the doc half of U10:

- Astro peer narrowed to `^7.0.0` (honest vs dual CI matrix).
- README states Astro is **required** for the schema stack (`astro/zod`), including `/server`-only hosts.
- Maintenance wiring is documented: default cron = stock release; outbox / ephemeral / account-delete need injects.
- Additive `/server/ports`, `/server/maintenance`, `/server/email` re-export current symbols without removing `/server`.

**However**, peer honesty is incomplete while `package-lock.json` and template docs still claim Astro 6 support. That undercuts the U09 exit criterion (“peer claim honest”) even though `package.json` itself is correct.

## Findings

### F1 — Medium: `package-lock.json` still advertises Astro `^6 || ^7`

`package.json` peer was narrowed to `^7.0.0`, but the lockfile root package record still has:

```text
packages[""].peerDependencies.astro = "^6.0.0 || ^7.0.0"
```

This commit did **not** refresh the lockfile. Tools/readers that trust the lock’s embedded package metadata still see a dual-major peer claim after U09.

**Ask:** regenerate/sync lock so root `peerDependencies.astro` matches `package.json` (`^7.0.0`).

### F2 — Medium (doc drift, outside diff but blocks “peer claim honest”): template README still says Astro 6 or 7

`src/templates/astro/README.md` still states:

> Supported template installs target Astro 6 or 7, matching Mika's peer dependency range.

That contradicts the new peer table. Not introduced by this commit, but left live it reopens the honesty hole U09 was meant to close.

**Ask:** update template install docs to Astro 7-only (or explicitly mark 6 unsupported).

### F3 — Low: new `/server/*` subpaths not mentioned in README host surface

README peer + maintenance sections are good. The “Three host faces” / supporting entrypoints prose still only names `/server` as the kitchen sink; it does not point hosts at:

- `@bnomei/emdash-mika/server/ports`
- `@bnomei/emdash-mika/server/maintenance`
- `@bnomei/emdash-mika/server/email`

Discoverability was the point of U15; package exports alone help tooling more than humans.

**Ask:** one sentence or table row listing the additive subpaths and when to prefer them over full `/server`.

### F4 — Low: package-exports contract samples symbols, does not pin parity

`test/package-exports.ts` imports a few types/factories from the new subpaths into `PackageEntryContract`. That proves the subpaths resolve and export *something*, not that they stay a complete re-export of the intended `/server` slices.

Drift risk is low today (thin hand-written barrels), but a single `typeof createMikaEmailOutboxRunnerFromServerEmail` field will not catch a dropped type from `email.ts`.

**Suggestion:** optional identity/parity pins, e.g. `createMikaEmailOutboxRunnerFromServerEmail` assignable both ways to the `/server` factory, and a ports key-set comment or type-level `Pick` equality for the port union. Not required for ship if barrels stay one-liners.

### F5 — Nit: maintenance sample is not copy-paste complete

The README inject example leaves `repositories: { /* comments */ }` and `createMikaEmailOutboxRunner({ /* host sender + repos */ })`. Correct as a *shape* sketch; hosts still need real ports. Acceptable for U10 docs half.

**Suggestion:** link to a template host file or list the `Pick<>` keys (`account | ephemeral | ledger | ops | session | stock`) so inject surface is discoverable without reading `plugin.ts`.

### F6 — Nit: dual-pin “closed” language vs remaining P1.1 work

Commit body and ROADMAP ticks correctly treat schema-contracts dual-pin as P1.1 *exit safety net*. Prefer-`z.infer` and intentional-divergence-at-schema remain open. No action if ROADMAP keeps those boxes open (it does).
