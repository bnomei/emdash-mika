## Summary

F1.1 lands real nominal brands: required unique-symbol phantoms on `SellableId` / `PriceId` / `CartId` / `CheckoutSessionId` / `OrderId`, entity constructors with `createMikaId` validation parity, Zod mint schemas via `brandedStringSchema`, public exports on `/types` and `/types/primitives`, and a types-only contract file that proves pairwise incompatibility and rejects bare `MikaId → entity`. No silent `as Brand` casts appear outside the mint helpers in `primitives.ts`.

F1.2 migrates the high-ROI surface correctly: public Inputs (via Zod) and money-path DTOs/documents use entity brands; ACP session records brand `cartId` / `checkoutId` while ACP **wire** item ids stay `string` and mint at `parseAcpItemId`; stock lifecycle reserve/consume correlation fields are branded; templates mint `CheckoutSessionId` from query params. Grep shows no scattered `as SellableId` / `as CartId` / etc. outside constructors.

F1.3 updates the hand `MikaActions` face so JSON clients use `SellableId` (stock.availability) and `CheckoutStatusInput` (checkout.status, already branded via schema). Form clients remain `FormData` transport. Bidirectional tree pin remains.

**Verdict:** Accept with residual gaps. Brand foundations and public Input/DTO/action paths meet the cards. The incomplete work is **depth of internal brand migration**: many money-path backend/port helpers and the hand `MikaApi` / facade / client stock.availability face still widen ids to `MikaId` or `string`, which re-opens wrong-entity assignability after the F1.1 unique-symbol fix. No runtime correctness defects found; issues are type-safety completeness.

### Non-issues / confirmed correct

- **Brand lattice:** Entity brands assign *to* `MikaId` (supertype escape) but not the reverse; entities are pairwise incompatible. Matches F1.1 recommended strategy.
- **Mint boundary discipline:** No `as SellableId` / `as CartId` / `as PriceId` / `as CheckoutSessionId` / `as OrderId` outside `create*` in `primitives.ts`.
- **ACP wire vs domain:** `MikaAcpItem.id` stays string; parse → `createSellableId` / `createPriceId`. Session record stores branded `cartId` / `checkoutId`.
- **Templates:** `checkout/success.astro` and `checkout/cancel.astro` call `createCheckoutSessionId(checkoutId)` on search-param strings before API calls — correct edge mint (not branding the wire URL itself).
- **Form vs JSON:** Form action clients stay `FormData`; entity schemas still mint brands inside Zod at the form parse edge (`cartAddForm*`, `checkoutStartForm*`, etc.).
- **Line ids / wishlist ids / stockItemId / subscriptionId:** Remain `MikaId` — consistent with “leave low-risk metadata” and no dedicated brand types yet.
- **Provider external refs** (`providerPriceId`, Stripe ids, etc.): Stay plain `string` / generic `MikaId` where appropriate.
- **`factory.ts` stock.availability** remints with `createSellableId(sellableId)` at the backend edge when the hand face still accepts `string` — correct runtime mint even though the face is under-branded (Issue 2).

## Issues

### Issue 1 -- Severity: suggestion

- File: src/api/backend/ports.ts:81
- Description: F1.2 acceptance requires branded params at **internal money-path boundaries**, but repository ports and several backend helpers still type cart/checkout/order/sellable/price correlation ids as bare `MikaId`. Because every entity brand is assignable *to* `MikaId`, a `CartId` can still be passed where a `SellableId` or `CheckoutSessionId` is intended once values cross these APIs — exactly the mixup F1.1’s unique-symbol brands were meant to block. Highest-signal residual sites:
  - `MikaCatalogRepositoryPort.findItemBySellableId(sellableId: MikaId)` — `ports.ts:81`
  - `findPriceById(priceId: MikaId)` — `ports.ts:86`
  - `claimCartForCheckout` / `releaseCartCheckoutClaim` both take `cartId: MikaId` and `checkoutId: MikaId` (swappable) — `ports.ts:123–132`, mirrored in `session.ts:167–189`
  - `findOrderById` / `findOrderByCheckoutSession` — `ports.ts:235`, `249`
  - `findBySellableId` on stock — `ports.ts:399`
  - `findOwnedOpenCartById(cartId: MikaId)` — `cart.ts:571`
  - `findQuoteCart` / `findOwnedCartById` — `quote.ts:301`, `320`
  - `selectCartPrice(priceId: MikaId | undefined)` — `quote.ts:779`
  - `findCheckoutStartCart(cartId: MikaId | undefined)` — `checkout/start.ts:637`
  - `resolveCheckoutStartLine` lineInput `sellableId` / `priceId` as `MikaId` — `checkout/start.ts:655–656`
  - `persistCheckoutStart` / `releaseCartCheckoutClaimQuietly` / `cartWithCheckoutReservations` take `checkoutId: MikaId` — `checkout/start.ts:800`, `892–893`, `960`
  - webhook `findExistingPaymentOrder(..., checkoutSessionId?: MikaId)` — `webhooks/payment/shared.ts:104`
  - provider money line `MikaProviderLineItem.sellableId: MikaId` / `priceId?: MikaId` — `provider.ts:200–201`
- Suggestion: Narrow port + helper signatures on money-path ids to the entity brands (`SellableId`, `PriceId`, `CartId`, `CheckoutSessionId`, `OrderId`). Prefer doing `claimCartForCheckout` / `releaseCartCheckoutClaim` first (two different brands side-by-side). Keep true generics (`createId` outputs, line/item ids without brands, customerId) as `MikaId`.
- Status: open
- Commit: d5047dd

### Issue 2 -- Severity: suggestion

- File: src/api/server.ts:75
- Description: Public operation input for stock availability is branded (`stockAvailabilityInputSchema` → `{ sellableId: SellableId }`), and F1.3 brands the JSON action client the same way. The hand **`MikaApi`**, **operation facade**, and **browser client** faces still accept bare `string`:
  - `MikaApi.stock.availability(input: { sellableId: string })` — `server.ts:75`
  - `MikaOperationFacade.stock.availability(sellableId: string)` — `operation-facade.ts:141`, implementation `295–296`
  - `MikaClient.stock.availability(sellableId: string)` — `client.ts:52`
  Because entity brands are subtypes of `string`, a host can still call `api.stock.availability({ sellableId: someCartId })` without a type error. Runtime mint in `factory.ts:80` only re-brands as `SellableId`; it cannot detect wrong entity. F1.3 fixed Actions only; dual truth remains for the other two host faces.
- Suggestion: Align hand faces with `z.infer` / `{ readonly sellableId: SellableId }` (and prefer `CheckoutStatusInput` already used for checkout.status on facade). Client/search-param transport can stay string *into* parse helpers, but typed method params should match operation Inputs. Soft-break for hosts that passed unminted strings into typed facade/API calls — they would mint via `createSellableId` at the call site.
- Status: open
- Commit: e6718fd
