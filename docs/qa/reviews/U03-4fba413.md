**Roadmap:** P0.2 MikaApi satisfies / registry method names  
**Scope:** `src/api/server.ts` only (+29 / −1)  
**Verdict:** **Approve** — closes the bidirectional method/namespace hole; no P0/P1 defects.

---

## Summary

This commit upgrades the one-way `defineMikaApiMethodNames` gate (previously only
`MissingMikaApiMethods`: every `MikaApi` method must appear in the name map) into a
true **bidirectional** compile-time pin between hand-written `MikaApi` and registry-
derived `mikaOperationApiMethodNames`.

| Direction | Mechanism |
| --------- | --------- |
| Registry method ∉ `MikaApi` | `TNames extends MikaApiMethodNameMap` (array elements must be `keyof MikaApi[K]`) |
| `MikaApi` method ∉ registry map | `MissingMikaApiMethods` |
| Registry namespace ∉ `MikaApi` | **New** `ExcessMikaApiNamespaces` |
| `MikaApi` namespace ∉ registry map | fails `extends MikaApiMethodNameMap` (required keys) |

`MikaApiMethodNameDrift` unions the residual checks and feeds both:

1. The `defineMikaApiMethodNames` parameter conditional (`… extends never ? TNames : never`)
2. An explicit `_AssertMikaApiMethodNamesPinned` zero-runtime const next to
   `mikaApiMethodNames` (documents the pin; same drift predicate)

This matches U03 intent (EXECUTION: compile-time helper types over runtime) and
aligns with the later U04/U05 pin style. Runtime coverage already existed via
`test/index.test.ts` (ops method set ≡ `mikaApiMethodNames`); this is the type-level
counterpart that fails **typecheck** when either surface drifts.

**Out of unit scope (intentional residual):** signature / arity / `ctx`-first
parameter shape are **not** pinned — only method **names** and **namespaces**.
Roadmap wording (“method presence; ctx rules as far as practical”) leaves ctx for a
deeper follow-up; commit message correctly scopes to method names.

## Issues

_No blocking or should-fix defects in this diff._

### Nits (optional polish; not required to keep the pin correct)

1. **Weaker failure diagnostics than U04**  
   `_AssertMikaApiMethodNamesPinned` resolves to `true | never`. On failure, TS
   reports roughly “`true` is not assignable to `never`” without surfacing *which*
   methods/namespaces drifted. U04 uses  
   `Drift extends never ? true : Drift` so the residual union appears in the error.  
   Same applies to `defineMikaApiMethodNames`’s `never` parameter.  
   **Suggestion:** mirror U04:

   ```ts
   type _AssertMikaApiMethodNamesPinned =
     MikaApiMethodNameDrift<typeof mikaOperationApiMethodNames> extends never
       ? true
       : MikaApiMethodNameDrift<typeof mikaOperationApiMethodNames>;
   ```

2. **`MissingMikaApiMethods` drops namespace qualification**  
   Indexing the mapped type with `[keyof MikaApi]` yields a bare method-name union
   (e.g. `"get"` with no `catalog.` / `account.` prefix). Fine for the `extends never`
   lock; slightly poorer if diagnostics are improved (nit #1). Could keep a mapped
   residual `{ [K in keyof MikaApi]: … }` and only collapse when checking `never`, or
   use `` `${K & string}.${…}` `` keys. Non-blocking.

3. **Dual enforcement is redundant by design**  
   `defineMikaApiMethodNames(...)` and `_assertMikaApiMethodNamesPinned` run the same
   drift predicate on the same value. Commit message says the assert is for explicit
   documentation — acceptable. Not a defect; avoid “simplifying” one away without
   keeping a single obvious failure site.

### Non-issues / confirmed correct

- Comment that extra *methods* in a known namespace are rejected by
  `extends MikaApiMethodNameMap` is accurate under `const` type parameters.
- `ExcessMikaApiNamespaces` is necessary: structural `extends` allows extra keys.
- Pin targets the **typed** `MikaOperationApiMethodNames` surface (cast on
  `collectMikaApiMethodNames()`), which is the right SoT for compile-time drift vs
  hand `MikaApi`.
- No runtime behavior change; stubs still iterate `mikaApiMethodNames`.
- Zero-runtime `void _assert…` pattern matches U04/U05 and is tree-shake / strip
  friendly under `erasableSyntaxOnly`.
