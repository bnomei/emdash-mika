## 1. Summary

The commit correctly severs the browser `/client` graph from the Zod-bound operation IR:

```text
Before:  client → routes → operations → validation → astro/zod
After:   client → routes → route-paths   (data-only)
         operations → route-paths + assert at module load
```

`src/api/route-paths.ts` is a pure, Zod-free map (`mikaPluginRoutePaths` + `publicMikaPluginRouteNames`). `routes.ts` imports only that module. Server-side collectors re-export the pure map and run a load-time consistency assert against IR `routeKey` / `routePath` / `public`.

That is the right architectural shape for P0.3. Residual risk is not “client still pulls Zod”; it is **dual SSOT** (paths live in both IR and `route-paths.ts`) and the **strength of the bridge** between them (runtime assert + casts vs compile-time pins used elsewhere in Wave 1).

Secondary edits (facade/actions pin inlining; barrel-test formatting) are out of the purity critical path and are noted only briefly.

## 2. Import graph purity

### 2.1 Intended graph (achieved)

| Module | Role after commit | Must stay free of |
| ------ | ----------------- | ----------------- |
| `route-paths.ts` | Data-only SSOT for browser URL keys/paths | `operations`, `validation`, `astro/zod` |
| `routes.ts` | URL builder + public re-exports | same |
| `client.ts` | Public catalog/stock HTTP client | same |
| `request.ts` | Envelope fetch helper | same (via `routes` only) |

`client.ts` imports:

- `./routes` (value + `MikaPublicPluginRouteName`)
- `./request` (value)
- `./types` (type-only DTOs / `MikaApiResult`)
- `../internal/object` (`optionalProperty`)

`routes.ts` imports only `./route-paths` and `../internal/object`. No edge to `operations` remains on the client path.

### 2.2 What purity does *not* mean

- **Full route map still ships to the browser.** `mikaPluginRoutePaths` includes admin/webhook/account keys, not only the two public client routes. `/client` only *types* public names (`MikaClientRouteName = MikaPublicPluginRouteName`), but the runtime map object is the full key set. That is acceptable for a shared URL helper; it is **not** a Zod/IR leak. Optional later tightening: public-only map for the client entry (size/hygiene, not correctness).
- **Type-level cycles** (`request.ts` ↔ `client.ts` types) pre-exist and are orthogonal to Zod purity.
- **`types.ts` / primitives** on the client graph are fine (no Zod).

Commit body / EXECUTION §3.3:

```bash

rg -n "astro/zod|operations-" dist/api/client.mjs dist/*operations* 2>/dev/null || true
```

**Pass criteria for P0.3:** `dist/api/client.mjs` (and its packed chunks reachable only from `/client`) must not import `astro/zod` or materialize the operations IR bundle that previously sat under `routes → operations`.

Review did not re-run pack; purity is assessed from source import edges in the commit, which match the unit design.

## 3. Assert consistency

Runtime bridge (in commit: `operations.ts`; later tree: `operation-collect.ts`):

`assertMikaPluginRoutesConsistent()` at module load, plus `assertRoutePathMatchesMap`.

### 3.1 What the assert covers (good)

| Check | Direction | Mechanism |
| ----- | --------- | --------- |
| IR key exists in pure map | IR → map | `routeKey in mikaPluginRoutePaths` |
| IR path equals map path | IR → map | string equality on `routePath` |
| Map key exists in IR (ops or route-only) | map → IR | `coveredKeys` vs `Object.keys(mikaPluginRoutePaths)` |
| Duplicate `path:method` among routed ops | IR internal | `Set` of `${routePath}:${httpMethod}` |
| Public route name **set** matches | IR ↔ map | sorted arrays from `public: true` vs `publicMikaPluginRouteNames` |

Together these are a **bidirectional runtime pin** for keys/paths and public flags — stronger than the old collector (which only built the map from IR and checked path conflicts / duplicate methods).

### 3.2 Assert / type-bridge weaknesses

| ID | Sev | Finding | Why it matters |
| -- | --- | ------- | -------------- |
| A1 | **Med** | `mikaOperationPluginRoutes = mikaPluginRoutePaths as typeof mikaPluginRoutePaths & MikaOperationPluginRoutes` is an **unchecked cast**. TypeScript will not fail typecheck if IR key sets or literal path types diverge from the pure map. | Wave 1 pins elsewhere use real assignability (`extends never` / `satisfies`). This re-export looks typed but does not pin. Runtime assert is the real guard. |
| A2 | **Med** | Same pattern for public names: `purePublicMikaPluginRouteNames as readonly MikaOperationPublicRouteName[]`. | Compile-time will not catch “public list includes a non-public IR key” or missing public keys; only the load-time set compare does. |
| A3 | Low | Public **order** is documented as public contract, but the assert **sorts both sides**. Order drift is only locked by tests (`publicMikaPluginRouteNames` deep equality), not by the assert. | Acceptable if full test gate always runs; assert message should not be read as order-safe. |
| A4 | Low | Assert runs only when the operations/collect module is evaluated. Pure `routes` / `client` imports never run it. | Full gate + server entrypoints import operations; still a gap for “client-only” test subsets. |
| A5 | Low | Public derivation walks **routed operations only**, not route-only definitions. Route-only `public: true` would not enter `derivedPublic`. | Today both route-only entries are `public: false`. Fragile if route-only public routes appear later. |
| A6 | Nit | No negative unit test that deliberately mismatches map vs IR and expects throw. | Confidence is integration-only (happy path + full map snapshot tests). |

### 3.3 Assert consistency verdict

**Adequate for P0.3 ship** if CI always loads operations (it does via normal tests/backend). **Weaker than Wave 1 compile pins** for the dual-map relationship: drift fails at **import time / test**, not at **typecheck** when editing one side only without running the graph that evaluates the assert.

Recommended follow-up (not blocking U06 purity):

1. Prefer `satisfies` / key-set equality types so `mikaPluginRoutePaths` is assignable to a mapped type derived from IR route keys (or the reverse) **without** `as`.
2. Keep runtime assert for path **string** equality and duplicate methods (harder to express purely at type level once paths are widened to `string` on the IR base type).
3. Optionally extend public derivation to route-only if those can ever be public.

## 4. Dual SSOT drift risk

### 4.1 Model after this commit

There are **two** written sources of path truth:

| Source | Consumers | Authority claimed |
| ------ | --------- | ----------------- |
| `route-paths.ts` (`mikaPluginRoutePaths`) | `/client`, `routes.ts`, re-export as `mikaOperationPluginRoutes` | “Pure / browser SSOT” |
| Operation IR (`routeKey` + `routePath` on each op / route-only) | Dispatch, descriptors, handlers via `mikaRouteOperationsByPath` | Still the server IR |

Comments that call `route-paths` *the* pure SSOT are accurate for **URL construction**. They are **not** accurate as “single place paths are written.” Adding or renaming a route is now a **two-file edit** (IR definition + `route-paths.ts`), where pre-U06 collected the map from IR alone.

That tradeoff is intentional and correct for browser purity; it must be treated as **managed dual truth**, not accidental leftover.

### 4.2 Drift scenarios

| Scenario | Caught by | Severity if missed |
| -------- | --------- | ------------------ |
| New op with new `routeKey`/`routePath`; map not updated | Load assert (missing key in map) | High — server fails fast |
| Map gains orphan key | Load assert (key not in IR) | Medium — dead client URL key |
| Path string differs IR vs map | Load assert | **Critical** — client would hit wrong path vs server |
| `public: true` flipped in IR only | Load assert (public set) | High — auth surface mismatch vs `publicMikaPluginRouteNames` / client types |
| Public list reordered only | Tests (not assert) | Low — contract order |
| Only map updated; tests that never import operations | **Not caught** | High in theory; low under full gate |
| Cast hides type-level key mismatch | typecheck green; assert still catches at runtime | Medium process smell |

### 4.3 Add-op workflow regression (process)

Pre-U06: path map derived → one write site for paths.  
Post-U06: developer must remember `route-paths.ts`. Forgetfulness fails loudly when operations load (good), but the **cognitive dual write** is the main residual tax of P0.3.

Mitigations already present:

- Full map equality snapshot in `test/index.test.ts` (`mikaPluginRoutes` deep equal).
- Public names order locked in the same suite.
- Load-time assert with explicit error strings pointing at `route-paths.ts`.

Mitigations still missing:

- Compile-time dual-pin (see A1/A2).
- CONTRIBUTING / “add an operation” checklist line: “also edit `route-paths.ts`”.
- True single SSOT designs (e.g. pure path map imported *into* definitions so IR does not restate path strings) — larger than U06; do not scope-creep here.

### 4.4 Dual SSOT findings

| ID | Sev | Finding | Recommendation |
| -- | --- | ------- | -------------- |
| D1 | **Med** (accepted risk) | Dual write of every path string is permanent until a later single-SSOT redesign. | Document in add-op guidance; keep assert + snapshot tests green as release blockers. |
| D2 | **Med** | Unchecked `as` casts weaken the type story for the dual map. | Follow-up: replace with `satisfies` / bidirectional key pins aligned with U03–U05 style. |
| D3 | Low | “Pure SSOT” wording in comments can mislead maintainers into deleting IR paths or treating the map as server dispatch truth. | Prefer “browser SSOT; IR remains dispatch SSOT; assert bridges them.” |
| D4 | Low | Snapshot tests duplicate the full map a **third** time (test literals). | Known pattern; any path rename is triple-touch (IR + map + test). Acceptable drift armor. |

## 7. Actionable follow-ups

Default EXECUTION policy is fix-all; for **this** unit the purity deliverable is already correct. Treat the following as **post-U06 hardening**, not a request to revert the purity split.

| Priority | Item | Rationale |
| -------- | ---- | --------- |
| P1 | Replace `as typeof map & MikaOperationPluginRoutes` with a real type pin (`satisfies` / key-set `_Assert…`) | Aligns with Wave 1 drift-armor; closes silent typecheck hole |
| P1 | Same for public route name list vs `MikaOperationPublicRouteName` | Public auth surface is security-adjacent |
| P2 | Document dual-edit requirement next to op definition or in add-op docs | Process mitigation for dual SSOT |
| P2 | Soften “the SSOT” comments to “browser SSOT + IR bridge” | Avoid wrong mental model |
| P3 | Negative test: mismatched path throws at import | Locks assert behavior |
| P3 | Consider public-only map for `/client` bundle size | Optional hygiene |

**Do not** “fix” dual SSOT by re-importing operations into `routes.ts` — that undoes P0.3.

## 8. Verdict

**Approve with follow-ups.**

- **Import graph purity:** Pass. The structural bug called out in external-api-surface (client → routes → operations → `astro/zod`) is fixed at the source layer.
- **Assert consistency:** Pass for runtime bidirectional coverage of keys/paths/public sets; **gap** on compile-time pins and public-order enforcement (tests only).
- **Dual SSOT drift:** **Accepted residual risk** of P0.3. Bridge is good enough under full gate; strengthen with type-level pins so path dual-truth matches the quality bar of U03–U05 registry pins.

No code changes required to close U06 purity itself; follow-ups are hardening against the dual-write tax the purity fix introduces.
