## Summary

These three commits land useful, low-churn drift armor: F0.3 replaces the tautological admin runtime coverage case with real sorted key-set equality against `mikaAdminActionDefinitions` and switches membership to `Object.hasOwn`; F0.4 samples public symbols through the published `@bnomei/emdash-mika/types/primitives` subpath in `package-exports.ts` (so `types:check` fails if the export map or DTS surface breaks); F0.5 adds process comments plus a single validation→`api/types` SoT equality sample; F2.3 adds a source-walk unit test that allowlists only `api/operation-define.ts` for the dynamic-dispatch double-cast patterns.

F0.3 and F0.4 actually fail when their contracts break. F0.5 still does **not** make “new public `*Input` omitted from the pin list” a type error by construction (the residual U02 called out, which F0.5 was meant to close). F2.3 catches the intended reintroduction paths under `npm test` / CI, with a few false-negative cousin patterns and comment-text false-positive risk.

**Verdict:** **Accept** F0.3 and F0.4 as closed. **Accept with residual** F0.5 (process armor improved; automatic discovery not delivered). **Accept** F2.3 for practical CI enforcement; tighten cousins / wiring wording if a follow-up touches the guard again.

## Issues

### Issue 1 -- Severity: suggestion
- File: `test/types-barrel-completeness.ts:1-14` (lists + map through L154); sample at `156-158`
- Description: F0.5 acceptance requires that adding a new public `*Input` without listing it “fails automatically or is impossible by construction.” After `babb83b` + `d912a6a`, completeness is still a **hand-maintained triple** (API import block, barrel import block, `PublicOperationInputPairs`). Omitting a brand-new `FooInput` from this file while exporting it from validation/`api/types`/`src/types/index.ts` still typechecks. The validation SoT pin only covers `AddCartItemInput` and does not close the discovery gap called out in U02 Issue 1. The header correctly documents the residual, so this is honesty debt vs the card’s checked acceptance, not a silent lie in-file.
- Suggestion: Prefer key discovery (`import type * as Api` / barrel, filter `` `${string}Input` ``, assert `Exclude<…>` is `never`) or a single shared name tuple used for imports + pairs so extending the SoT without the pin is impossible. Keep the one-line validation sample as an extra SoT check, not the completeness mechanism.
- Status: fixed (autofix 2026-07-09)
- Commit: `d912a6a` (and docs half in `babb83b`)

### Issue 2 -- Severity: suggestion
- File: `test/no-ad-hoc-mika-api-cast.test.ts:12-15`
- Description: Forbidden patterns cover `as unknown as MikaApi` and the exact `Record<string, Record<string, unknown>>` double-cast, but not close cousins that reintroduce dynamic API dispatch, e.g. `as any as MikaApi`, `as unknown as any`, or `as unknown as Record<string, any>`. A new ad-hoc cast could land outside the allowlist without failing the pin. File-level allowlist on `operation-define.ts` is correct for the current site; cousin false-negatives are the gap.
- Suggestion: Extend `FORBIDDEN` with `as\s+any\s+as\s+MikaApi\b` and optionally a looser `as\s+unknown\s+as\s+Record<\s*string\s*,` (or AST-based ban of double assertions targeting `MikaApi` / string-index API bags). Keep the allowlist file-only.
- Status: fixed (autofix 2026-07-09)
- Commit: `11b59ae`

### Issue 3 -- Severity: nit
- File: `test/no-ad-hoc-mika-api-cast.test.ts:28-37`
- Description: The scanner matches raw file text, so a documentation comment or string outside the allowlist that literally contains `as unknown as MikaApi` (or the Record form) is a **false positive**. The allowlisted file already documents the MikaApi form in a comment; that is fine only because the whole file is skipped. Gate wiring is `npm test`, not `npm run check` as F2.3 acceptance text claims — CI still runs tests, so this is process wording / local-only-check drift, not a missing CI gate today.
- Suggestion: Strip block/line comments before matching, or implement as an oxlint/eslint restriction so `npm run check` matches the card. Align ROADMAP “Verify / Acceptance” wording with `npm test` if the unit-test approach stays.
- Status: fixed (autofix 2026-07-09)
- Commit: `11b59ae`
