## Findings

### F1 — README heading hierarchy regression (medium / docs structure)

**Where:** `README.md` after insert of `## Three host faces`

**Issue:** Inserting a new `##` section between Install content and the pre-existing `### Errors` / `### Maintenance wiring` headings reparents those subsections under **Three host faces** instead of **Install** (or their own top-level sections).

Current outline:

```text
## Install
  ### Peer requirements
## Three host faces          ← new
  ### Errors                 ← was not about host faces
  ### Maintenance wiring     ← was not about host faces
## Examples
```

TOC/sidebar and readers now treat error-code policy and maintenance cron wiring as part of “three host faces,” which dilutes the mental-model section and buries install-flow prose (“Create a host entrypoint…”) under the wrong parent.

**Suggested fix (docs-only):**

1. Keep `## Three host faces` as a short, self-contained section (table + supporting entrypoints paragraph only), **or**
2. Demote it to `### Three host faces` under `## Install` if it is meant as install orientation, **or**
3. Promote Errors / Maintenance to `##` so they are siblings again.

Preferred: (1) or (3) so “three faces” stays a first-class, scannable model without absorbing unrelated install topics.
